## 결론

소프트웨어 결함을 수정하고 하드웨어 없는 회귀 테스트를 추가했습니다.
**이 기록은 실제 운행 안전 확인서가 아닙니다.** 이번 점검에서는 모터·로봇팔을 실제로 움직이지 않았습니다.
Pi의 다른 프로젝트 전체를 감사하거나 현장 전원·배터리·배선·기계적 상태를 검사한 것도 아닙니다.

| 브라우저가 사라져도 실기 권한 유지 | 화면 heartbeat 1초, 서버 5초 임대 만료 시 정지·잠금 시도 |
| HTTP 오류를 정지 성공처럼 표시 | 성공 응답 확인, 정지 처리 여부와 물리 정지 확인 구분 |

## 변경된 운전 규칙

- 기본은 데모. `--sensors-only`와 기존 `--hardware` 모두 **이동 잠금**으로 시작합니다.
- 화면에서 안전 확인 후 실기모드 요청 → I2C 읽기 응답 및 정지 명령 처리 → 임시 운전 권한을 발급합니다.
- 수동 이동은 최대 속도 80, 일반 이동 0.5초, 시간 기반 회전 4초입니다.
- STOP·안전모드·창 비활성화·리모컨 닫기·통신 오류 뒤에는 다시 안전 확인해야 합니다.
- 다른 탭의 상태 조회만으로 운전 권한을 얻거나 갱신할 수 없습니다.
- 새 프로토콜은 `safety_protocol: 2`입니다. 서버와 두 UI를 함께 업데이트하고 브라우저를 새로고침합니다.
- 스페이스바는 입력창 밖에서 정지합니다. **Escape는 입력 중에도 정지**합니다.

## 검사한 원격 범위

점검 당시 SSH 기기는 `tracelab-desktop`, Raspberry Pi 5 / Ubuntu 24.04였습니다.
`chan` 실행 파일, 관련 가상환경, 디스크·메모리·포트·서비스 상태를 확인했습니다.
`8090` 라즈봇 서버와 `8000` 카메라 서버는 초기 점검 시 실행 중이 아니었습니다.
초기 점검 시 I2C 장치 파일은 존재했지만 실제 `0x2B` 응답·모터 동작은 재시험하지 않았습니다.

`can0.service`는 `203/EXEC` 실패 상태였으며, 서비스 파일에 `/sbin/sudo`와 셸 전용 문법이 들어 있었습니다.
CAN 서비스를 사용하기 전 팔 장치의 버스·핀·비트레이트와 서비스 설정을 확인해야 합니다.
`RobotUnified_v2`, Klipper, Moonraker는 별도 점검이 필요한 연계 서비스입니다.

## 여전히 남는 위험

1. Python 프로세스 강제 종료·전원 손실·OS 정지·I2C 통신 멈춤은 소프트웨어 watchdog으로 보장할 수 없습니다. 별도 모터 컨트롤러 watchdog과 물리 비상정지가 필요합니다.
2. STOP은 진행 중인 **정상적인 시간 대기**를 취소합니다. I2C 드라이버 호출 자체가 멈추면 지연될 수 있습니다. 5초 임대는 하드 실시간 정지 보장이 아닙니다.
3. HTTP STOP 처리 성공은 바퀴가 실제로 멈췄다는 센서 피드백이 아닙니다. 직접 확인하고 실패하면 본체 전원을 차단하세요.
4. 로그인 인증·TLS·사용자 권한 관리가 없습니다. 토큰은 실수 방지용 제어권이며 신원 인증이 아닙니다. 인터넷에 공개하지 말고 SSH 터널 또는 신뢰하는 망에서만 사용하세요. Origin 검사도 악성 로컬 클라이언트나 DNS rebinding에 대한 완전한 방어가 아닙니다.
5. 시간 기반 회전은 각도 정확도를 보장하지 않습니다. 배터리·노면·바퀴 방향에 따라 보정해야 합니다.
6. 자율 시뮬레이터는 가상 장치에서 실행합니다. 실제 주행·팔 제어 연동 시에는 별도 하드웨어 어댑터와 감독하의 실물 시험이 필요합니다.
