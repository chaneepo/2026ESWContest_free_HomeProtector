# 라즈봇 집 지도 시뮬레이션

로봇청소기처럼 집을 탐색하고 방을 구분한 뒤 목적지로 이동하는 화면 시연이다. 실제 SLAM, 카메라 분석, LiDAR 측정, 로봇 운전 기능이 아니다.

## 사용 방법

1. 웹의 **라즈봇 · 집 지도** 메뉴를 연다. 초기 화면은 사전 정의된 예시 평면도 미리보기다.
2. **집 탐색 시작**을 누른다. 충전소에서 출발하며, 가상 센서가 확인한 영역만 지도에 표시된다.
3. 1×·2×·4×로 재생 속도를 조절하거나 일시정지·재개한다.
4. 탐색이 끝나면 거실·주방·침실 2개·욕실 2개·현관·서재 중 목적지를 선택하고 **가상 이동**을 누른다.
5. 충전소 복귀 또는 서재 출입 제한을 시험한다. 제한 구역 안에 로봇이 있거나 경로 이동 중이면 제한을 새로 설정할 수 없다.
6. **가상 지도 초기화**는 메모리의 진행 상황만 초기화한다.

앱 내부의 다른 메뉴를 열면 이동을 멈추고 지도를 보존한다. 창이 비활성화되거나 전체 비상정지가 발생해도 멈추며, 다시 움직이려면 재개해야 한다. 새로고침하면 초기화된다. 지도나 분석 결과를 DB에 저장하지 않는다.

## 가상 데이터와 계산 기준

- 예시 지도: 28×30 격자, 한 칸 0.4m. 사용자 참고 도면의 중앙 거실·식사 공간, 좌측 주방·서재, 우측 침실·욕실, 하단 현관 배치를 단순화했다. 도면의 치수를 정밀 복제한 것이 아니며 방·가구 이름도 AI가 분류한 결과가 아니다.
- 화면에는 격자를 그리지 않는다. 인접한 칸의 공유 변을 제거하고 연결된 윤곽선으로 합쳐, 방별 연속 색상 영역과 벽 외곽선을 표시한다. 내부 격자는 경로·센서 계산에만 사용한다.
- 벽·가구 경계에는 좌표 기반의 고정된 미세 계단과 스캔 점을 합성한다. 경계 변형은 최대 약 0.334칸인 화면 효과이며, 실제 센서 오차나 측정 결과가 아니다. 경로·충돌 판정·탐색률에는 영향을 주지 않는다.
- 탐색 경로: 예시 전체 지도에서 통과 가능한 칸을 방문하는 결정적 순회. 미지 환경을 자율적으로 탐색하는 실제 알고리즘은 아니다.
- 가상 센서: 최대 4.5칸 거리까지 광선을 진행하며 첫 벽·가구에서 멈춘다. 가구 경계를 접촉한 경우 예시 가구 정보를 표시한다.
- 탐색률: 가상 센서가 확인한 이동 가능 칸 / 전체 이동 가능 칸. 방별 분석 완료도 같은 기준으로 계산한다.
- 목적지 경로: 4방향 최단 경로, 벽·가구·제한 구역 제외. 실제 로봇 크기, 회전 반경, 제동 거리 및 위치 오차 검증은 미구현이다.
- 가상 가용면적: 방의 이동 가능한 격자 개수 × 0.16㎡. 건축 면적이나 실제 측정 면적이 아니다.
- 가상 이동 거리: 이동한 격자 수 × 0.4m. 로봇 센서 측정값이 아니다.

## 실물과의 분리

`frontend/views/MappingPage.tsx`와 `frontend/mocks/homeMapping.ts`는 실물 클라이언트를 가져오지 않고 API 요청도 하지 않는다. 실기 리모컨은 왼쪽 **라즈봇 리모컨** 메뉴에서만 열리며 지도 화면에는 마운트하지 않는다. 리모컨 진입만으로 운전 권한을 얻지 않으며, 안전 확인 후 실기모드 선택이 필요하다. 메뉴 이탈 시 기존 정지·잠금 처리를 수행한다. 지도 내 **모의 정지**는 가상 이동만 멈춘다.

**중요:** 상단의 기존 **전체 비상정지**는 안전 기능을 보존하기 위해 실제 라즈봇 정지 API도 요청한다. 그 응답만으로 실제 바퀴 정지를 보장하지 않는다. 지도 시뮬레이션 검사에서는 이 API를 호출하지 않는다.

## 검사

프로젝트 루트에서 Node.js 22.13 이상으로 실행한다.

```sh
npm --prefix frontend run test:mapping
(cd frontend && npx tsc --noEmit --incremental false)
npm --prefix frontend run build
```

자동 검사는 경로 연속성, 장애물 회피, 전체 탐색, 가상 센서의 벽 차단, 제한 구역, 정지·재개, 복귀, 초기화, 네트워크 분리, 참고 배치, 합성 경계의 결정성·변형 범위·계산 분리를 다룬다. 실제 모터·카메라·DB는 사용하지 않는다.

## 실제 인식 연동 시 필요한 것

센서 좌표계와 로봇 좌표계 보정, 실제 위치 추정, 지도 갱신, 동적 장애물 및 이동 여유 공간 검증, 지도 버전 저장, 하드웨어 실행 결과 피드백이 필요하다. 현재 시뮬레이션 상태를 실제 장치의 성공 상태로 사용하면 안 된다.
