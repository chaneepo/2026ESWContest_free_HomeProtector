# 개발 로드맵

## 1. 우선순위

현재 보유 장비를 기준으로 가장 먼저 증명해야 할 것은 다음 한 줄이다.

> 카메라가 물품을 찾고 → SO-ARM101이 물품을 집고 → 가방에 넣고 → 실제 들어갔는지 확인한다.

앱, 라즈봇, 날씨 기능보다 이 폐루프의 반복 성공률과 안전성을 먼저 확보한다.

## 2. 단계별 계획

| 단계 | 결과물 | 현재 상태 | 완료 기준 |
|---|---|---|---|
| 1. 제어센터 UI | 한국어 대시보드와 기능 화면 | 완료 | 주요 6개 화면 탐색 가능 |
| 2. 실행 시뮬레이션 | 상태 흐름, 이벤트, 실패 주입 | 완료(제한 있음) | 정상/복구 흐름 시연 가능 |
| 3. SO-ARM101 단독 제어 | Home, pose, 그리퍼, stop | 계획 | 실제 장비 반복 명령 및 오류 확인 |
| 4. marker 비전 | ID와 camera pose 검출 | 계획 | 고정 환경에서 목표 정확도 달성 |
| 5. 좌표 변환·Pick & Place | robot pose와 동작 연결 | 계획 | 지정 물품 반복 이동 성공 |
| 6. 센서 검증 | 가방 무게 변화 판정 | 계획 | PLACE와 실제 적재 성공 구분 |
| 7. Execution Engine | 서버 상태기계·복구·영속화 | 계획 | 재시작 후 상태 복원 및 실패 소진 처리 |
| 8. Planning Engine | 목적·사용자·날씨 규칙 | 계획 | 규칙 근거와 필수/선택 물품 생성 |
| 9. 귀가 후 분류 | 물품별 기본 위치 복귀 | 일부 UI 시뮬레이션 | PACK과 다른 실제 SORT 검증 |
| 10. 라즈봇 연동 | 이동 플랫폼 작업 전달 | 계획 | 도킹과 작업 handoff 성공 |
| 11. 방별 배송 | 방/목적지 단위 배송 | 계획 | 위치별 전달과 복귀 성공 |
| 12. 재난 Priority Mode | 비상 물품 우선 계획 | 계획 | 안전 정책과 우선순위 시험 |
| 13. 사용자·보호자 앱 | 일정, 알림, 원격 확인 | 계획 | 권한별 핵심 흐름 완료 |
| 14. 통합 시험 | 장시간·장애·안전 시험 | 계획 | 정의한 KPI와 안전 기준 충족 |

## 3. 다음 개발 스프린트 권장 범위

1. SO-ARM101 SDK/통신 방식 확인과 최소 adapter 작성
2. 실제 Home, Safe, 그리퍼 명령 및 STOP 응답 시간 측정
3. 고정 카메라와 marker 3개 인식
4. 수동으로 측정한 고정 pose를 이용한 첫 pick & place
5. 모든 명령과 검증을 구조화 이벤트로 기록

이 스프린트에서는 사용자 계정, 일정, 날씨, Razbot을 범위에서 제외한다.

## 4. 단계별 핵심 지표

- 비전 검출률과 pose 오차
- pick 성공률, place 성공률, 검증 정확도
- 물품 1개당 평균 처리 시간
- STOP 요청부터 실제 정지까지의 최악 시간
- 오류 유형별 자동 복구 성공률
- 장시간 반복 시 통신 단절과 데이터 손실 건수

## 5. 릴리스 게이트

실장비 모드는 다음 조건을 만족할 때만 일반 UI에서 활성화한다.

- 물리 E-stop과 소프트웨어 STOP 시험 완료
- 안전 작업 공간과 속도 제한 적용
- 좌표 보정 버전 확인 가능
- 영구 이벤트 로그와 장애 원인 추적 가능
- 시뮬레이션과 실장비 모드가 명확히 표시됨
- 운영자가 수동 복구 절차를 숙지함
