# 시뮬레이션 모드

## 1. 목적

시뮬레이션 모드는 실제 장비 없이 화면, 작업 상태 전이, 이벤트, 실패 복구 계약을 검증하기 위한 개발 기능이다. 장비 성능이나 물리적 성공률을 증명하지 않는다.

## 2. 구성 파일

| 경로 | 역할 |
|---|---|
| `mocks/mockData.ts` | 장치, 물품, 인식, 작업, 이벤트 초기값 |
| `mocks/simulationEngine.ts` | 단계 실행, 지연, 취소, 실패 주입 |
| `store/SystemProvider.tsx` | 물품별 실행, 상태·이벤트·이력 갱신 |
| `services/*.ts` | 비동기 mock 호출 경계 |

## 3. 현재 실행 규칙

- 활성 물품 중 최대 4개를 작업에 포함한다.
- PACK은 목적지를 `외출 가방`으로 설정한다.
- SORT는 각 물품의 기본 목적지를 사용한다.
- 물품별로 `PLAN → DETECT → PICK → MOVE → PLACE → VERIFY`를 실행한다.
- DETECT, PICK, MOVE는 약 1.1초, 다른 단계는 약 0.75초 대기한다.
- 모든 물품 성공 후 작업은 `SUCCESS`, 시스템은 `COMPLETE`가 된다.
- 브라우저 새로고침 시 실행 상태와 수정 데이터가 초기화된다.

## 4. 실패 주입

자동 작업 화면에서 `NONE`, `PICK`, `VERIFY` 중 하나를 선택할 수 있다. 실패 대상은 첫 번째 물품에만 적용되며 한 번 실패한 후 `RECOVER`를 거쳐 같은 단계를 한 번 재실행하면 성공한다.

현재 제한:

- 재시도 소진에 따른 최종 `FAILED` 경로가 없다.
- UI의 “최대 2회 재시도” 문구와 엔진의 1회 재시도가 일치하지 않는다.
- DETECT, MOVE, PLACE, 센서 통신 실패는 주입할 수 없다.
- 시간 지연과 성공 결과는 실제 장비 특성을 반영하지 않는다.

## 5. 취소와 비상정지

중지 요청은 엔진의 cancel flag를 설정한다. 다음 취소 확인 지점에서 `CANCELLED` 오류가 발생하고 provider가 작업을 `CANCELLED`, 실행 상태를 `ERROR`로 기록한다. 비상정지도 같은 취소 기전을 사용하면서 로봇 상태와 비상정지 flag를 추가로 설정한다.

이는 UI 동작 확인용이다. 실장비의 즉시 정지 보장과는 다르다.

## 6. 실장비 모드로 교체

`SystemMode`에는 `REAL` 값이 있지만 전환 UI와 실제 어댑터는 없다. 전환 시에는 다음 원칙을 적용한다.

1. View와 도메인 타입은 유지한다.
2. `services/*.ts`를 REST/실시간 client로 교체한다.
3. 실행 상태의 기준을 서버 Execution Engine으로 이동한다.
4. 시뮬레이션 failure target은 개발 환경에서만 노출한다.
5. 서버와 장치의 연결 상태를 실제 heartbeat로 판단한다.
6. 시뮬레이션과 실장비 이벤트에 `mode`를 기록한다.

## 7. 권장 테스트 시나리오

- 정상 PACK, 정상 SORT
- PICK 1회 실패 후 성공
- VERIFY 1회 실패 후 성공
- 각 상태에서 작업 중지
- 각 상태에서 비상정지 후 reset
- 활성 물품 0개일 때 작업 시작 차단
- 새로고침 및 네트워크 재연결 시 서버 상태 복원
- 실장비 adapter contract test와 mock 결과 비교
